# How the sitemap and robots.txt are created

This document describes how `public/sitemap.xml` and `public/robots.txt` are produced, where the URL list comes from, and how the project keeps them in sync with the app.

## Overview

Both files are **generated by a Node script** rather than maintained by hand. That keeps every public URL aligned with the same inventory the verification tooling uses.

| Output | Path | Generator |
|--------|------|-----------|
| XML sitemap | `public/sitemap.xml` | `scripts/generate-seo.ts` |
| robots.txt | `public/robots.txt` | `scripts/generate-seo.ts` |

Next.js `src/app/sitemap.ts` and `src/app/robots.ts` are **not used**  -  static files in `public/` are served at `/sitemap.xml` and `/robots.txt`.

Canonical host: **https://www.damagesexpertwitness.co.uk**

## URL inventory (`buildPublicUrlInventory`)

The script imports `buildPublicUrlInventory` from `src/lib/seo/publicUrlInventory.ts`. That function assembles all paths that should appear in search, then maps them to absolute URLs with the canonical host.

The inventory merges:

- **Static app routes**  -  `APP_STATIC_PATHS`: home, services, types-of-damages, practice-areas hub, case-types hub, what-is, qualifications, how-to-instruct, fees, faq, guides hub, experts, glossary.
- **Practice area pages**  -  `/practice-areas/:slug` (4 slugs from `src/data/practice-areas.ts`).
- **Case type pages**  -  `/case-types/:slug` (12 slugs from `src/data/case-types.ts`).
- **Guide pages**  -  `/guides/:slug` (6 slugs from `src/data/guides.ts`).

**Excluded from the sitemap** (`SITEMAP_EXCLUDED_PATHS`):

- `/contact`  -  conversion page (indexable but not in sitemap)
- `/thank-you`  -  `noindex, nofollow`
- `/privacy`  -  `noindex, follow`
- `/terms`  -  `noindex, follow`

The combined list is deduplicated, sorted, and exposed as `allUrls` (absolute) and `allPaths` (pathname only).

## Sitemap generation (`scripts/generate-seo.ts`)

For each URL in `inventory.allUrls`, the script emits a standard sitemaps.org `<url>` entry with:

- `<loc>`  -  The absolute URL.
- `<lastmod>`  -  The calendar date when generation runs (`YYYY-MM-DD` in UTC via `toISOString()`).
- `<changefreq>`  -  Heuristic by path (home `weekly`, others `monthly`).
- `<priority>`  -  Heuristic by path (see `getSitemapPriority()` in `publicUrlInventory.ts`).

The full document is written to `public/sitemap.xml`. The `public/` directory is created if needed.

## robots.txt generation (`scripts/generate-seo.ts`)

`robots.txt` is rendered from `ROBOTS_DISALLOW_PATHS` in `publicUrlInventory.ts` (not from the sitemap URL list). It:

- Allows all crawlers on `/` by default.
- Disallows paths that should not be crawled as normal HTML: `/admin/`, `/api/`, `/private/`, `/.netlify/`, `/thank-you`.
- Declares the sitemap location: `Sitemap: https://www.damagesexpertwitness.co.uk/sitemap.xml`.

The file is written to `public/robots.txt`.

## Commands

From the repo root:

```bash
npm run seo:generate   # Regenerate sitemap.xml + robots.txt
npm run seo:verify     # Fail if sitemap or robots drift from inventory
npm run build          # Runs seo:generate, then next build
```

Run `seo:generate` after:

- Adding static routes to `APP_STATIC_PATHS`
- Adding slugs to practice-areas, case-types, or guides data
- Changing `ROBOTS_DISALLOW_PATHS` or the canonical host
- Before a release when you want fresh `lastmod` dates

## Continuous integration

`.github/workflows/seo-checks.yml` runs on pull requests and manual dispatch:

1. `npm ci`
2. `npm run seo:generate`  -  Regenerates files and catches generation failures.
3. `npm run seo:verify`  -  Compares `public/sitemap.xml` `<loc>` entries and `robots.txt` rules to the inventory so committed files cannot drift.

## Deployment (Netlify)

`netlify.toml` sets explicit content types:

- `/sitemap.xml` → `Content-Type: application/xml`
- `/robots.txt` → `Content-Type: text/plain`

Files in `public/` are served from the site root at `https://www.damagesexpertwitness.co.uk/sitemap.xml` and `/robots.txt`.

## Operational notes

- Canonical host is defined in `CANONICAL_HOST` inside `publicUrlInventory.ts` (overridable via `NEXT_PUBLIC_SITE_URL`). Update it and regenerate if the primary domain changes.
- New static pages must be added to `APP_STATIC_PATHS` or `seo:verify` will fail after the next generate.
- This site has no Blog Maker / dynamic blog URLs  -  the inventory is fully static + data-driven slugs.
